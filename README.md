# 社区长者智能手环告警家属确认与上门处置平台

面向社区独居老人照护场景的告警处置系统（前端单页应用）。手环上报跌倒、心率异常、长时间静止、离家未归、设备离线等告警后，平台按**告警类型、最近活动轨迹、历史误报、家属联系方式、社区值班人员**自动生成处置流程；家属端确认，社区端上门处置，全程（告警 → 确认 → 上门 → 处置 → 就医 → 回访）记录在同一事件内，结案后生成复盘报告并沉淀**照护画像**。手环**连续两天低电且未充电**时，平台按佩戴习惯与历史告警提示家属/社区上门检查，家属确认已提醒仍未充电则安排志愿者协助，低电期间离线自动纳入事件复盘，闭环时登记充电协助人与恢复时间，设备再次低电则提示更换设备或充电底座。

## 技术栈

React 18 · TypeScript · Zustand · React Router · Ant Design 5 · Vite

## 功能地图

| 模块 | 说明 |
| --- | --- |
| 告警工作台 | 待处理/升级/已结案统计、低电照护风险横幅，事件列表筛选，模拟手环上报 |
| 低电照护 | 手环连续两天低电且未充电自动建单：按佩戴习惯与历史告警提示家属/社区上门检查 → 家属确认已提醒仍未充电则安排志愿者协助 → 登记充电协助人与恢复时间；再次低电提示更换设备或充电底座；低电期间离线自动关联事件复盘（设备维护不及时） |
| 事件处置 | 自动生成的处置流程（含每步依据）、升级情形（家属超时/电话无人接/低电/夜间浴室/上门无人开门/联动物业/联动120/低电维护不及时）、家属与社区双端操作、全程时间线 |
| 老人档案与设备 | 姓名、住址、慢病、紧急联系人、常用活动范围、设备电量（含连续低电天数标记）、佩戴习惯、告警阈值（可在线调整） |
| 结案复盘 | 误报原因、设备调整建议（按原因自动生成）、设备维护复盘（低电期间离线）、家属响应时长、社区处置时效；事件分类：设备误报 / 照护缺口 / 真实风险 |
| 照护画像 | 结案/低电建单自动沉淀：连续无人响应、频繁离线、多次上门无人在家、连续低电未充电 → 画像标签与风险等级；社区可调整巡访频次、设备维护、家属提醒方式 |
| 家属端门户 | 确认误报 / 请求电话核实 / 要求上门 / 直接拨打120，查看低电照护提醒并确认已提醒老人充电，查看事件进展与历史复盘 |

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173
```

生产构建与预览：

```bash
npm run build
npm run preview    # http://localhost:4173
```

端到端流程自测（告警→超时升级→家属响应→上门→物业/120→就医→回访→结案→画像沉淀，以及低电照护全链路，共 64 项断言）：

```bash
npm run test:flow  # 输出 ALL CHECKS PASSED 即通过
```

## 验证方式（本题核心流程）

以下验证均已在本地实际执行：`npm run build` 构建通过；`npm run test:flow` 64 项断言全部通过；`vite preview` 下页面正常返回 HTTP 200。

1. **登录社区端**（community/123456）→ 工作台可见 1 条进行中的「跌倒告警」（王秀兰，浴室，夜间，等级：紧急）与 1 条「设备离线」上门中事件，另有 2 条已结案事件（真实风险、设备误报）；顶部出现「设备低电照护风险」横幅（李建国手环连续低电 2 天未充电）。
2. **打开跌倒事件** → 中部为自动生成的处置流程（通知家属 → 家属确认 → 网格员上门 → 联动物业/120 → 回访结案，每步标注生成依据）；左侧为老人档案（慢病、联系人、轨迹、门禁、钥匙托管、上次回访）。
3. **家属超时升级** → 点击顶栏「演示时间快进 +5分钟」（或等待 3 分钟）→ 事件出现「家属超时未响应」升级标记，时间线自动追加记录。
4. **家属确认** → 退出登录，改用 family/123456 进入家属端 → 对告警执行「要求上门查看」（也可在社区端事件页用「家属端操作模拟」面板操作）。
5. **社区上门** → 回到社区端：派单上门（自动匹配就近网格员）→ 记录到达 → 记录结果；选择「无人开门」会触发升级并解锁「联动物业开门 / 使用托管钥匙」；选择「需医疗处置」后呼叫 120 并记录就医结果。
6. **回访结案** → 记录回访 → 结案并选择事件分类（设备误报需选误报原因）→ 自动生成复盘报告：误报原因、设备调整建议、家属响应时长、社区处置时效。
7. **画像沉淀** → 进入「照护画像」页：该老人的误报/缺口/风险计数、家属未响应、上门无人等指标已更新，画像标签与风险等级自动重算，可调整巡访频次、设备维护、家属提醒方式。
8. **阈值调整** → 「老人档案与设备」页可修改心率/静止/围栏/归家阈值与佩戴习惯，保存后用于后续告警判定与复盘建议；设备电量 ≤20% 的行会显示「连续低电 N 天·未充电」标记。
9. **模拟新告警** → 工作台「模拟手环上报」可任选老人、告警类型（跌倒/心率异常/长时间静止/离家未归/设备离线）与位置，验证不同告警生成的差异化处置流程（如低电量老人会追加「设备维护」步骤，浴室/夜间自动升级）。
10. **低电照护全链路（本题新增）**：
    - 进入「低电照护」页：种子任务 **BC-0001（李建国）** 已连续低电 2 天以上，家属（儿媳刘芳）已确认提醒但老人仍未充电（第 2 次连续低电），页面列出按佩戴习惯（全天佩戴、可能不会用充电底座）与历史告警生成的上门检查提示；
    - 点击「安排志愿者上门协助」→ 系统按楼栋就近派单（5栋→小马）→ 记录志愿者上门 → 登记充电协助人与恢复时间（设备电量恢复 100%、清空连续低电计时）；因是第 2 次，闭环后出现**更换设备/充电底座**提示，可登记「更换充电底座」或「更换整只手环」；
    - 自行模拟一条新链路：页面右上「模拟手环电量上报」任选老人上报 12% → 顶栏「演示时间快进」快进 2 天 → 系统自动建单（状态：待家属确认）并沉淀画像标签「连续低电未充电」；点「家属确认：已提醒老人充电」后任务推进，随后可安排志愿者；
    - 低电任务进行中时在工作台「模拟手环上报」一条**设备离线**告警 → 事件自动关联该低电任务、触发「低电设备维护不及时」升级、流程追加「连续低电照护干预」步骤；结案复盘报告中出现**设备维护复盘**项（设备维护不及时作为事件复盘的一部分）。
    - 家属端（family/123456，绑定王秀兰 e1）门户顶部展示低电照护提醒与佩戴习惯检查提示，并可一键「我已提醒老人充电」。演示方法：先用社区端在「低电照护」页对王秀兰上报 12% 并快进 2 天使其建单，再换 family 账号登录即可看到提醒卡。

## 演示说明

- 家属响应超时阈值演示设为 **3 分钟**（顶栏「演示时间快进」可立即触发）。
- 连续低电判定为 **2 天**：低电照护页「模拟手环电量上报」选老人上报 12% 后，用顶栏「演示时间快进」快进 2 天即自动建单；种子数据已预置 1 条进行中的低电照护任务（李建国 BC-0001）。
- 数据为内存态（Zustand），刷新页面后重置为种子数据。
- 项目类型为前端单页应用，按题目约束不提供 Swagger/OpenAPI。
