# 社区长者智能手环告警家属确认与上门处置平台

面向社区独居老人照护场景的告警处置系统（前端单页应用）。手环上报跌倒、心率异常、长时间静止、离家未归、设备离线等告警后，平台按**告警类型、最近活动轨迹、历史误报、家属联系方式、社区值班人员**自动生成处置流程；家属端确认，社区端上门处置，全程（告警 → 确认 → 上门 → 处置 → 就医 → 回访）记录在同一事件内，结案后生成复盘报告并沉淀**照护画像**。

针对**设备低电导致的照护风险**，平台另设「设备低电照护」工单：手环连续低电未充电时，依据老人**佩戴习惯与历史告警**提示家属/社区上门检查；家属确认已提醒但老人仍未充电，社区可安排**志愿者上门协助充电**；若低电期间发生离线告警，事件复盘将「设备维护不及时」纳入结论；低电处理完成后记录**充电协助人与恢复时间**；设备再次低电时系统提示是否**更换设备或充电底座**。

## 技术栈

React 18 · TypeScript · Zustand · React Router · Ant Design 5 · Vite

## 功能地图

| 模块 | 说明 |
| --- | --- |
| 告警工作台 | 待处理/升级/已结案统计，事件列表筛选，模拟手环上报；连续两天低电未充电的老人置顶红色横幅提示 |
| 事件处置 | 自动生成的处置流程（含每步依据）、升级情形（家属超时/电话无人接/低电/连续两天低电/低电期离线维护不及时/夜间浴室/上门无人开门/联动物业/联动120）、家属与社区双端操作、全程时间线 |
| 设备低电照护 | 低电跨天自动计天、按佩戴习惯+历史告警生成上门风险提示、家属确认已提醒/提醒后仍未充电、社区安排志愿者协助、记录充电协助人与恢复时间、低电期离线纳入复盘、再次低电提示更换设备/充电底座、历史处理记录 |
| 老人档案与设备 | 姓名、住址、慢病、紧急联系人、常用活动范围、设备电量（标注进行中的低电工单）、佩戴习惯、告警阈值（可在线调整） |
| 结案复盘 | 误报原因、设备调整建议（按原因自动生成）、**设备维护及时性复盘（低电期离线认定维护不及时）**、家属响应时长、社区处置时效；事件分类：设备误报 / 照护缺口 / 真实风险 |
| 照护画像 | 结案自动沉淀：连续无人响应、频繁离线、多次上门无人在家、低电照护次数、维护不及时次数、志愿者协助充电次数 → 画像标签与风险等级；社区可调整巡访频次、设备维护、家属提醒方式 |
| 家属端门户 | 确认误报 / 请求电话核实 / 要求上门 / 直接拨打120；**低电提醒确认、提醒无效时一键请求志愿者上门协助充电**，查看事件进展与历史复盘 |

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173
```

生产构建与预览：

```bash
npm run build
```

## 验证方式（本题核心流程）

以下验证均已在本地实际执行：`npm run build` 构建通过；`npm run test:flow` 63 项断言全部通过（输出 `ALL CHECKS PASSED`）；`vite preview` 下页面正常返回 HTTP 200。

1. **登录社区端**（community/123456）→ 工作台可见 1 条进行中的「跌倒告警」（王秀兰，浴室，夜间，等级：紧急）、1 条「设备离线」上门中事件（陈守仁）、1 条李建国的「设备离线」事件（低电期间离线），另有 2 条已结案事件；顶部红色横幅提示**李建国手环连续两天低电未充电**。
2. **打开跌倒事件** → 中部为自动生成的处置流程（通知家属 → 家属确认 → 网格员上门 → 联动物业/120 → 回访结案，每步标注生成依据）；左侧为老人档案（慢病、联系人、轨迹、门禁、钥匙托管、上次回访）。
3. **家属超时升级** → 点击顶栏「演示时间快进 +5分钟」→ 事件出现「家属超时未响应」升级标记，时间线自动追加记录。
4. **家属确认** → 退出登录，改用 family/123456 进入家属端 → 对告警执行「要求上门查看」（也可在社区端事件页用「家属端操作模拟」面板操作）。
5. **社区上门** → 回到社区端：派单上门（自动匹配就近网格员）→ 记录到达 → 记录结果；选择「无人开门」会触发升级并解锁「联动物业开门 / 使用托管钥匙」；选择「需医疗处置」后呼叫 120 并记录就医结果。
6. **回访结案** → 记录回访 → 结案并选择事件分类（设备误报需选误报原因）→ 自动生成复盘报告：误报原因、设备调整建议、家属响应时长、社区处置时效。
7. **画像沉淀** → 进入「照护画像」页：该老人的误报/缺口/风险、家属未响应、上门无人、低电照护、维护不及时、志愿者协助等指标已更新，画像标签与风险等级自动重算，可调整巡访频次、设备维护、家属提醒方式。
8. **阈值调整** → 「老人档案与设备」页可修改心率/静止/围栏/归家阈值与佩戴习惯，保存后用于后续告警判定与复盘建议。
9. **设备低电照护（本题新增）**：
   - 工作台横幅或左侧「设备低电照护」菜单进入 → 李建国工单 **BC-2001**：手环已**连续 2 天低电未充电**，页面依据其「全天佩戴」习惯（不便自行取下，疑底座故障）与历史误报/低电期离线记录给出上门风险提示。
   - 打开关联事件 **EV-1003**（低电期间离线）→ 升级标记含「低电期间设备离线（维护不及时）」；左侧可直接联动处理低电工单。
   - 家属视角：用 **family2/123456** 登录 → 门户顶部展示低电照护卡（种子数据中家属此前已确认提醒），直接显示「已提醒但老人仍未充电，请求志愿者上门协助」；对一条新发生的低电（如低电页模拟某老人低电后，由其家属账号查看），则先显示「我已提醒老人充电」，确认后才出现请求志愿者按钮。
   - 社区视角：在工单上「安排志愿者上门协助」（自动匹配负责5栋的志愿者小马）→ 记录到达 → 记录协助结果（已充上电/老人不配合/手环故障/底座故障）→「完成低电处理」登记**充电协助人、恢复后电量**，系统记录**恢复时间**并关闭工单，画像同步沉淀。
   - **事件复盘**：将 EV-1003 走完上门/回访/结案 → 复盘报告出现「设备维护复盘：设备维护不及时」结论及说明，画像新增「设备维护不及时」标签，设备维护策略升级为「每日跟踪电量」。
   - **再次低电提示更换**：低电照护页右上「模拟电量上报」选择李建国上报 12% → 自动新建工单并提示「该设备再次低电（上一次工单 BC-2001 已闭环），是否需要更换设备或充电底座」→ 社区可登记更换手环/更换充电底座/暂不更换加强提醒。
   - **自动升级与自动闭环**：对任一老人上报 ≤20% 电量即生成首日低电工单（自动推送家属）；顶栏「快进 1 天」后工单自动计为连续两天并升级「建议上门检查」；低电期间再模拟「设备离线」告警会自动关联工单并触发维护不及时升级；上报 50% 以上电量工单自动闭环。
10. **模拟新告警** → 工作台「模拟手环上报」可任选老人、告警类型（跌倒/心率异常/长时间静止/离家未归/设备离线）与位置，验证不同告警生成的差异化处置流程（如低电量老人会追加「设备维护（低电照护）」步骤，浴室/夜间自动升级）。

## 演示说明

- 家属响应超时阈值演示设为 **3 分钟**（顶栏「演示时间快进」可立即触发）；「快进 1 天」可驱动低电工单跨天升级。
- 低电量阈值 20%，连续低电 **2 天**未充电触发上门检查提示；电量回升至 20% 以上即视为恢复并自动关闭低电工单。
- 数据为内存态（Zustand），刷新页面后重置为种子数据。
- 项目类型为前端单页应用，按题目约束不提供 Swagger/OpenAPI。
